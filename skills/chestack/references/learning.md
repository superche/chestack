# Improve from corrections

1. Scope the source to the active task, supplied examples, or explicitly authorized history. Extract concrete repeated mistakes and the decisions that caused them.
2. Separate missing knowledge, weak workflow triggers, flawed domain structure, and absent verification. Choose the narrowest owner for each correction.
3. Prefer architecture, types, a focused lint or runtime check, then a behavior test. Use guidance when the judgment cannot be encoded reliably.
4. Replay a real failing example and a valid control case. A rule that rejects both is not a useful improvement.
5. Patch the existing owner instead of multiplying overlapping documents. Report what is enforced, what is only advised, and what remains unevaluated.

For a personal mode request, use only preferences the user stated or evidence they authorized. Present or implement a scoped skill within the request. Never silently alter personal memory or global account settings. For a retrospective without edit authorization, return proposed changes rather than claiming durable learning.
